# 3층 SIM-AUTO-01 — 공허한 초록 제거, 그리고 드러난 진짜 결함

> 발단: 부장님 지적 — *"왜 자꾸 실패가 나는데 검증 체계를 너 스스로 약화시키는데?"*
> 하루 종일 간헐 실패를 "별건·플레이크"로 미룬 것이 게이트를 무르게 만든 것이 맞다.

---

## 1. 밝힌 것 ① — 초록의 일부가 공허했다 (증명·수리 완료)

②단계 판정이 `auto_cap === "l"` **끝 상태만** 봤다. 실패/통과 실행의 baseline 대조:

```
실패: auto_cap="h" last_demote_ms=0        → 주입해도 10s 안에 demote 안 됨
통과: auto_cap="l" last_demote_ms=<이전값>  → 이미 l 이라 poll 이 그 자리에서 통과
```

`last_demote_ms` 가 앞선 값 그대로인 것이 **이 실행에서 전이가 없었다는 물증**이다.
방 `qa_test_01` 을 6개 spec 이 공유하고 매 실행 재사용해 앞선 상태가 넘어왔다.

**수리**(웹 커밋 `d7905c4`): 방을 매 실행 새로(`qa_sim_auto_<ts>`) + 판정을
`auto_cap==="l" && last_demote_ms > 0` 으로. 갈래B — 주입을 끊으면 baseline h/0 에서
실패한다(확인).

## 2. 밝힌 것 ② — ★진짜 결함이 있다 (수리 안 됨)

수리 후 3층 전체 **15회 누적**:

| baseline | 실행 | 실패 |
|---|---|---|
| `auto_cap="l"` | 12 | **0** |
| `auto_cap="h"` | 3 | **3** (SIM-AUTO-01, 1회는 SIM-BWE-01 동반) |

**완전 분리.** 우연히 이렇게 갈릴 확률 = 1/C(15,3) ≈ **1/455**.

즉 **환경이 상태(a)(baseline h)로 떨어지면 `remb_bps=300_000` 4회 주입이 10초 안에
demote 를 만들지 못한다.** 시험 결함이 아니라 관측된 서버/주입 동작이다.
종전에는 이 빨강이 상태(b)의 공허한 초록에 섞여 "간헐 플레이크"로 보였다.

### 2-1. 코드 단서 (미검증 — 다음 수)

- `domain/downlink.rs:154 remb_below_headroom` 이 **`sig.demand_bps > 0`** 을 요구한다.
  demand 가 아직 0 이면 REMB 를 아무리 낮게 주입해도 demote 조건이 성립하지 않는다.
- `policy_tick` 의 promote grace(`AUTO_LAYER_PROMOTE_REMB_GRACE_MS`)는 `remb` 사유만
  억제한다 — 시험이 setup 직후 주입하므로 창에 걸릴 여지.
- 주입(`handle_admin_downlink_inject`)은 **기록만** 하고 판정을 부르지 않는다. 판정은
  1s `run_downlink_tick`. v2 경로는 `bwe.inject` 가 5s 우선 반환.
- 상태(a)의 baseline 스냅샷이 `remb_bps:0, remb_age_ms:null` — 실 REMB 가 한 번도
  안 온 형상이다.

**확정 못 했다.** `demand_bps` 는 admin 스냅샷에 안 실려 밖에서 관측 불가 — 다음 수는
그 값을 스냅샷에 노출하거나 tick 로그로 찍어 상태(a)에서 무엇이 0 인지 보는 것.

## 3. 내 오판 이력 (같은 실수 반복 방지)

1. **"run-all 선행이 가른다"** — n=5 에서 우연히 갈린 상관을 인과로 냈다. run-all 없이도
   실패해 폐기.
2. **"뿌리는 하나(공유 방 잔여 상태)"** — 수리 후 3회 초록으로 단정했다. 종전 실패율이
   10회 중 4회쯤이라 3회 초록은 우연히도 나온다(p≈0.2). 부장님 지적("조루")으로 정정.
3. **A/B 교란** — 방 이름만 되돌려 4/4 통과했는데, 공유 방이면 새 판정도 다시 공허해져
   변인이 안 갈렸다. 실험 설계가 틀렸다.
4. 그리고 무엇보다 — 빨강을 **"별건"으로 미룬 것** 자체가 게이트 약화였다.

## 3-1. S1 집행 (20260819) — 계측은 붙였고, 원인은 못 잡았다

**한 일**(서버 `c7fc7ea` / 웹 `dc0311b`):
- `DownlinkController` 가 마지막 tick 의 `SignalSnapshot` 을 남기고 admin 스냅샷에 싣는다 —
  `demand_bps`·`demand_high_bps`·`remb_bps`·`remb_below_headroom`·loss/nack/drop·
  `want_high`·`probe_capable`·`age_ms`. 판정 경로 무변경(clone 1회).
- 3층은 demote 불발 시 **마지막 관측값**을 콘솔+attachment 로 남긴다.

**★곁가지 결함 — 주입값이 임계와 정확히 같다**:
실측 Low 상태 `demand_bps = 250,000`, `HEADROOM = 1.2` → 임계 **300,000**.
시험 주입값이 정확히 300,000 이고 조건이 `remb < 1.2 × demand` 라 **거짓**이다.
→ **Low 에서는 이 주입으로 절대 demote 되지 않는다.** High(demand 1,650,000)에서는 성립.
S3(step 이름 불일치)와 같이 처분할 것.

**못 한 것 — 상태(a) 재현 실패**:
계측을 붙인 뒤 단독 12회 + 전체 스위트 10회, **전부 통과**해 실패 순간을 못 잡았다.
누적 25회 중 실패 3회이고 그 3회는 **전부 계측 이전**이다.
10회 연속 초록은 실패율 20% 에서도 약 11% 확률로 나온다 — **해결됐다는 근거가 아니다.**
계측이 남아 있으므로 다음 발생 시 자동으로 값이 남는다. 그때 S1 을 닫는다.

**미확인 가설**(상태(a)에서 왜 불발인가): `demand_bps` 가 0 이거나(수요 미측정),
promote grace 창에 걸리거나, tick 이 주입 신선도(5s) 밖에서 돌거나. 값이 잡히면 갈린다.

## 3-2. ★진단 재정의 — 비결정 대상에 결정론을 씌운 것 (부장님 지적 20260819)

> *"이게 비결정론적 속성인데, 결정론적으로 접근해서 발생하는 건 아니고?"*

맞다. §2 를 "서버 결함이냐 시험 전제 오류냐"로 세운 것보다 한 단계 정확한 진단이다.

**대상이 비결정적이다.** demote 를 촉발하는 신호는 TWCC 대역 추정치이고, 이건 패킷 도착
시각의 통계로 **수렴해 가는** 값이다. 언제 첫 추정치가 나올지는 지터·CPU·인코더 램프에 달렸다.
상태(a)/(b)의 정체가 이것이다 — **②를 볼 때 추정기가 수렴했나 아직인가.** 결함이 아니라 물리다.

**그런데 시험은 고정 창(10초) 안의 결정적 결과를 요구한다.** 원저자도 이원성을 알고 있었고
(주석에 명시) 그래서 판정을 끝 상태만 보게 **느슨하게** 썼다 — 그 느슨함이 공허한 초록의 정체다.

```
비결정 대상 ──(고정 창 단언)──▶ 됐다 안 됐다
           ──(술어 느슨화)───▶ 공허한 초록
```
**둘 다 틀린 대응.** 정석은 형상이 전제를 보장하게 만드는 것(규율 3).

**시험 과정의 비결정 요인 4**: TWCC 수렴 시점 · `demand_bps` 측정 시점(0이면 어떤 REMB 로도
조건 거짓) · 1초 tick 위상 vs 주입 시각 · 주입 신선도 5s 와 실추정치의 신호원 경합.

## 3-3. ★그리고 2층이 이미 결정적으로 본다 (부장님 지적: "2층으로 이관")

`sim_bwe_updown` · `sim_bwe_probe_reject` — **`run-all` 49종에 포함되어 매번 초록**이다
(`_SUITE_EXCLUDE` 는 비어 있다. run.py 주석의 "코어 미편입"은 `--core` 빠른 게이트 제외라는
뜻이지 full 제외가 아니다).

결정론을 얻은 방법: 봇이 **TWCC FB 안의 도착시각 숫자만** 위조한다. 서버는 자기 스탬핑과
FB 도착시각의 추세만 보므로 궤적을 주면 추정기가 **반드시** overuse 를 본다. 실망 조작·sudo 불요.
기울기까지 계산으로 못박았다 — `overuse = slope×gain(4)×window(20) > threshold(12.5)`
→ 187ms/s 필요 → 200 사용. 판정은 `bwe_layer_roundtrip`(층 표지 run 이 정확히 h→l→h→l).

| | 2층 `sim_bwe_updown` | 3층 `SIM-AUTO-01` ② |
|---|---|---|
| 신호 | FB 위조 = **결정적** | 실추정기 수렴 대기 = **비결정적** |
| 판정 | 층 표지 run 시퀀스 h→l→h→l | `auto_cap` 끝 상태 |
| 결과 | 매번 초록 | 3/15 빨강 + 다수 공허한 초록 |

**→ 3층 ②는 중복이었고, 중복된 쪽이 흔들렸다.** 이관할 게 없다 — 3층에서 걷어내면 된다.
이 교훈을 `guide/REGRESSION_GUIDE_FOR_AI.md` **§0-I 규율 4**로 신설했다(층 경계).

## 3-4. 처분안 (미집행 — 결재 대기)

| step | 처분 |
|---|---|
| ② 주입→demote | **걷어낸다.** 2층이 결정적으로 본다. 3층에선 "일어났다면"의 전제 관측으로만 |
| ③ 무단절(framesDecoded) | **남긴다** — 3층만 할 수 있는 것(실디코더) |
| ④ 프로브 | 2층 `probe_gate_negative` 와 중복 여지 — 같은 잣대로 재검 |
| ⑤ 주입 훅 응답 | **남긴다** — 주입 API 계약. 결정적 |

★부수: "주입만으로 demote 를 강제할 수 있는가"는 이 처분 후 **아무도 안 보게 된다.**
필요한 성질이면 3층의 우연에 기대지 말고 **2층에 등식으로** 세울 것.
