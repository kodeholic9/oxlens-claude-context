## A. 병렬 실행 — `run-all --jobs N` (`2883470`)

상세는 `guide/REGRESSION_GUIDE_FOR_AI.md` **§1-P**(단일출처). 요약만:

**근본 차단은 `user_id` 하나였다.** 서버 `PeerMap.by_user` 가 user_id 단일 전역 키(`peer_map.rs:45`)인데
실측으로 `botB` 46종 / `botA` 41종 시나리오 공유 → 동시 실행이 **원리적으로 불가능**.
orchestrator 가 방·user_id 에 시나리오 태그를 넣어 해소(`botA~conf_audio`).

| | 직렬 | 병렬(jobs=4) |
|---|---|---|
| 소요 | 11.5분 | **2분 38초** |

시각 지표는 **악화 없음**(최악 19→3ms, 24→6ms). 부수로 `_LAST`(순서 회피)가 불필요해졌다.

**태그가 하니스 버그 2건을 드러냈고 등식이 잡았다** — `SUBSCRIBE_LAYER` 의 `target` 미태그,
급사 마킹 `record_floor` 미태그(→ `adv_floor_failover` 가 **정당 발화 구간**을 "화자 없음"으로 오판).

**★조용한 무효화 1건 실측**: `floor_convergence` 의 `FLOOR_RACE_S`(100ms) 창과
`conf_floor_contention` 요청 간격이 **정확히 같아** 지터 1ms 로 등식이 조용히 skip 했다.
→ `expect_contention` 선언 게이트 + 간격 50ms. **병렬화의 대가는 임계 초과가 아니라 커버리지 소실 쪽이다.**

## C. RTCP 값 축 3종 (`62d88d7`)

종전 RTCP 축은 존재(`rtcp_present`)와 누설(`rtcp_terminate`) 둘뿐이었고 report block 은
**ssrc 만 남기고 내용을 통째로 버렸다**. loader 가 전부 적재하도록 고쳤다
(`fraction_lost`/`packets_lost`/`highest_seq`/`jitter`/`lsr`/`dlsr` + SR `rtp_ts`).

| 등식 | 보는 것 |
|---|---|
| `rr_uplink_clean` | 무손실 전제(§7-3)를 **서버 관점**으로 뒤집은 것 |
| `rr_highest_seq_sane` | 서버는 봇이 안 보낸 seq 를 봤다고 할 수 없다(시각 무관 축) |
| `rr_responsiveness` | 봇 SR 이후 RR 의 `lsr` 이 그 SR 의 NTP 중간32비트와 일치해야 |

**반응성은 서버가 이미 재고 있었다** — `rtcp_terminator.rs:45,197`(`last_sr_ntp_middle`/`dlsr`).
실측 `dlsr=39669` = 0.605초. **재는데 아무도 안 봤다.**
`dlsr` 상한은 발명하지 않고 측정으로만 남긴다.

| # | 등식 | 증상 | 실제 원인 |

| ① | `egress_delivery` | soak 20회 중 1회 `-1` | SR 인플라이트 중 RTP 추월. 여유가 **항상 정확히 0** |

②에서 오판을 두 번 했다 — *"PTT gating 이라 seq 가 끊겨 정상"*(→ 봇은 보낼 때만 seq 를 올린다,
`rtp_tx.py:44,50`), *"병렬 부하 탓"*(→ 직렬에서도 같은 빈도). **부장님이 "seq 불연속성을 서버가
맞춰주는거자나" 로 짚어 걷혔다.** 자료를 좁히기 전에 원인을 말한 것이 두 번 다 실수였다.

셋 다 해법이 같았다 — **경계가 아니라 정착 시점(마지막)을 본다.**

## E. 도구로 막았다 — 시각 섭동 메타 시험 (`38bc9bf`)

부장님: *"가이드에 넣는다구? 그럼 방어가 되? 도구에 문제가 있음 도구를 고쳐야지."*

```bash
python -m oxe2epy perturb
```

실 dump 의 수신 시각을 δ 만큼 **앞으로** 밀며 전 등식 재판정 → **판정이 처음 뒤집히는 δ**(시각 여유)를
등식마다 측정. **임계를 발명하지 않는다** — 여유를 재서 그 dump 의 **실측 전파지연 p95**(4.22ms)와 견준다.

음성 픽스처("안 깨지는 등식은 죽은 게이트")의 **짝**이다 — *"미세한 시각 흔들림에 뒤집히는 등식"*.

### 만들며 도구가 두 번 스스로를 고쳤다

1. **음(−) 방향 섭동은 물리적 불가**(응답이 요청보다 먼저). 1차 실행의 3건은 그래서 난 거짓 경보.
2. **recv 를 통째로 밀면 RTP·RTCP 상대 관계가 안 변해** 진짜 위험을 못 잡는다 → **경로별로** 민다
   (`all`/`rtcp`/`rtp`). 두 경로는 지연이 독립이다.

### 자기검증 — 그리고 내 "수리"도 틀렸다고 했다

`egress_delivery` 결함 버전을 되돌리니 **0.20ms 여유로 ★불안정** 적발.
그리고 **정정했다던 현행판도 1.00ms 로 불안정**이었다 — 음수만 막았지 RTP 가 RTCP 대비 늦는
양수 방향이 남아 있었다. → **시각 창을 아예 없앴다**: 마지막 SR 의 누적 송신 수 vs **전체 수신 수**.
시각을 안 쓰니 경계 race 자체가 없다. 감지력 유지 확인(240/230 적발, 240/245 통과).

**정직하게: 3건 중 1건만 잡는다.** ②③은 시각 창이 아니라 **표본 선택** 결함이라 사정거리 밖이다.
